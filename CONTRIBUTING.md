# Contribuir

Gracias por colaborar. El proyecto está en fase de diseño; consulta el README y la hoja de ruta antes de proponer cambios.

1. Describe el problema y el alcance en un issue, excepto si se trata de una vulnerabilidad: sigue SECURITY.md.
2. Crea una rama y mantén los cambios centrados en un objetivo.
3. Usa exclusivamente datos sintéticos o anonimizados. No incluyas endpoints ni credenciales reales.
4. Explica comportamiento, impacto en seguridad y validación en la pull request.

Al introducir código ejecutable, incluye instrucciones reproducibles y pruebas de los comportamientos críticos. Toda dependencia debe tener una necesidad concreta y una versión mantenida; conserva su lockfile. No añadas workflows que ejecuten código de contribuciones con secretos o permisos de escritura.

Las contribuciones se distribuyen bajo la licencia MIT del proyecto. Mantén un trato respetuoso y constructivo.
